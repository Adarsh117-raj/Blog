01 / Project overview

Why predict customer churn?

Subscription businesses lose recurring revenue when customers leave. Churn prediction aims to identify customers who may be at risk early enough for a business to consider retention actions, such as a discount or a longer contract.

Problem statement

Spreadsheets can show averages, but they do not provide an individual risk score. This project builds a free, easy-to-run tool that analyses customer data, highlights factors associated with churn and presents an individual prediction in a clear dashboard.

Project objectives

Generate customer records, explore churn patterns, train a Random Forest classifier, evaluate it with standard metrics and present the analysis through an interactive Streamlit dashboard.

02 / Technology stack

Tools behind the project

Each tool supports one stage of the workflow, from generating records and preparing data to model training and interactive visualisation.

Data preparation

NumPy generates synthetic customer records. Pandas loads the CSV, groups data for analysis and applies one-hot encoding to categorical fields.

Machine learning

Scikit-learn provides the Random Forest classifier, train-test split and evaluation metrics such as accuracy, precision, recall and confusion matrix.

Dashboard & charts

Streamlit builds the browser interface with tabs and input controls. Plotly Express creates interactive charts and the confusion-matrix heat map.

03 / System workflow

From raw records to churn risk

The system follows a simple three-stage architecture: data generation, analytics and presentation.

Generate the dataset

A Python script creates 2,000 synthetic customer records and saves them in customers.csv.

Load and encode data

Pandas loads the CSV. Contract and internet categories are converted into numeric columns using one-hot encoding.

Split and train

The dataset is split into 80% training data (1,600 records) and 20% test data (400 records). A Random Forest with 200 trees is trained.

Evaluate the model

The model predicts the test set. Accuracy, confusion matrix and feature importance are calculated.

Explore and predict

The dashboard displays charts and metrics, then accepts one customer's details to estimate churn probability.

06 / Limitations & future scope

A prototype that can grow

The current version demonstrates the complete workflow, while the report identifies clear next steps before it could be considered for real-world use.

Current limitations

  • Uses synthetic data rather than records from a real company.
  • Moderate accuracy; no hyperparameter tuning or cross-validation.
  • Uses only Random Forest, without comparison to other algorithms.
  • No login, database or automatic data refresh.
  • Predicts one customer at a time.
  • Real customer information would require secure handling, permission and fairness checks.

Planned improvements

  • Use a real dataset such as the Telco Customer Churn dataset.
  • Compare Logistic Regression, XGBoost and other models with cross-validation.
  • Apply grid search for tuning and address class imbalance.
  • Add SHAP values to explain individual predictions.
  • Support CSV upload for bulk prediction and downloadable high-risk lists.
  • Add SQL database storage and user login.
  • Deploy the dashboard to a cloud service for team access.
07 / Conclusion

Making data easier to act on

The Customer Churn Prediction Dashboard demonstrates an end-to-end data analytics and machine learning workflow: creating data, exploring patterns, training a classifier, evaluating results and presenting predictions through an interactive interface. The analysis linked month-to-month contracts, shorter tenure, fibre service, higher charges and more support calls with higher churn in the synthetic dataset.

Before applying this approach to a real business, it would need real customer data, careful validation and tuning, model comparison, and a review of privacy and fairness.
